Criando componentes — arquitetura proposta

Esta seção documenta a proposta de extensão para o futuro WMK Component SDK. A v0.5.2 ainda não carrega plugins externos automaticamente.

Objetivo

Permitir criar controles novos com propriedades e eventos próprios, inclusive variantes baseadas em controles existentes. Preferimos composição e registro de metadados a exigir herança JavaScript irrestrita.

Estrutura de exemplo

components/wmk-moeda/
  component.json
  index.js
  style.css
  README.md
  tests/

Manifesto conceitual

{
  "id": "wmk.moeda",
  "name": "WMK Moeda",
  "version": "0.1.0",
  "base": "TextBox",
  "properties": {
    "currency": {"type": "string", "default": "BRL"},
    "required": {"type": "boolean", "default": false}
  },
  "events": ["change", "validate"]
}

Contrato proposto

Os plugins deverão declarar render(), getValue(), setValue(), validate(), serialize() e dispose(). O Designer deverá mapear propriedades e eventos via schema e o runtime deverá aplicar permissões por extensão.

Exercício prático para desenvolvedores

  1. Copie o manifesto acima e altere o nome para WMKCEP.
  2. Defina a propriedade mask e a validação de CEP.
  3. Crie testes para entrada válida, entrada vazia e serialização.
  4. Após o SDK existir, registre o componente na Widget Box; antes disso, o manifesto é apenas documentação de arquitetura.

Evite implementar componentes como scripts com acesso irrestrito ao token da Bridge. A arquitetura precisa de isolamento, validação, controle de permissões e revisão de código.
