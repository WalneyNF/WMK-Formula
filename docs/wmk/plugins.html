Plugins, APIs, IA, Skills e MCP — plano

Nosso objetivo é permitir que aplicações web, IA e componentes usem uma interface documentada para operações autorizadas. Os recursos abaixo ainda são planejados.

Camadas propostas

CamadaResponsabilidade
Bridge APIContratos HTTP e eventos versionados
SDK JSFunções simples para componentes e aplicações
PluginsControles, fontes de dados e comandos extensíveis
Provedores de IAAdapters para Ollama, Groq, OpenAI, Gemini, etc.
SkillsInstruções e exemplos para agentes criarem sistemas dentro das APIs disponíveis
MCPFerramentas padronizadas para clientes e agentes compatíveis

Contrato futuro de uma ferramenta

{"name":"wmk_read_range","inputSchema":{
  "type":"object",
  "properties":{"range":{"type":"string"}},
  "required":["range"]
}}

Boas práticas

  1. Credenciais de IA e banco de dados ficam no backend, nunca em código-fonte publicado ou no JavaScript da página.
  2. Ferramentas que apagam ou sobrescrevem registros precisam de confirmação.
  3. Logs devem ocultar tokens e dados sensíveis.
  4. O agente só pode chamar ferramentas implementadas e testadas, não inventadas.
  5. Uma política de permissões por projeto é obrigatória antes de permitir extensões de terceiros.
