Como o WMK Formula foi construído e o que você pode fazer com ele

Propósito: permitir que pessoas que usam planilhas criem formulários, cadastros e automações com HTML, CSS e JavaScript, sem VBA. O Designer é independente do executável; a comunicação acontece por uma API local.

1. O que é e o que já funciona

O projeto combina o WMK Formula (aplicativo de planilhas Rust derivado do GridCraft), uma Bridge Python e um Web Designer. O editor visual roda no navegador; os dados continuam na planilha real do aplicativo.

Planilhas reais

Leitura e gravação de células pelo protocolo de controle Rust.

Formulários

Label, TextBox, TextArea, Button, CheckBox, ComboBox, DataGrid e Panel.

CRUD

Adicionar, localizar, selecionar, editar e compactar registros nas colunas mapeadas.

Monaco

Editar JavaScript, executar comandos permitidos e conferir o console.

Testado pelo usuário Envio e leitura de registros com quatro campos, incluindo TRUE/FALSE e opções de ComboBox. Ainda não implementado Banco SQLite integrado ao CRUD, plugins instaláveis, IA, MCP e tabelas dinâmicas.

Motor Rust: mantém a planilha, suas fórmulas e o estado do documento. Bridge: adapta os comandos do navegador ao protocolo de controle local. Designer: monta o formulário, mantém estado visual e envia solicitações. Monaco: editor de código web; não é um motor de planilhas. Runner: executor JavaScript experimental em documento isolado.

3. Primeiro contato no Windows

  1. Extraia o pacote web em D:\Ferramentas\WMK-Bridge.
  2. Mantenha o executável WMK Formula na localização esperada pelo inicializador (no ambiente de desenvolvimento, D:\Ferramentas\gridcraft\target\debug\WMK-Formula.exe).
  3. Abra INICIAR-WMK.cmd com duplo clique. Se algum caminho for diferente, consulte o arquivo iniciar.py e o guia README-INICIO.txt.
  4. No navegador, acesse http://127.0.0.1:8773/designer.html; o Code Studio fica em http://127.0.0.1:8773/.
  5. Em uma planilha de teste, crie três cadastros e confirme os valores nas células.

Segurança: o servidor deve continuar restrito ao computador local. Não exponha a Bridge à internet nem execute scripts desconhecidos. Não use uma planilha com dados importantes para os primeiros testes.

4. Como desenhar um formulário

  1. Abra o Designer. Use Widget Box para escolher um componente.
  2. Selecione e arraste no canvas; use as oito alças para mudar largura e altura.
  3. No Object Inspector, escolha o objeto; no Property Editor, altere nome, texto, posição, tamanho, aparência e comportamento.
  4. Use F5 para alternar para Execução. Durante a execução os controles recebem entradas do usuário.
  5. Salve o projeto em JSON, guarde uma cópia e teste a opção Abrir JSON.

O arquivo de formulário JSON armazena controles e propriedades; ele não é um aplicativo publicado por si só. Publicação autônoma, layouts avançados e eventos próprios de cada componente ainda são objetivos de evolução.

5. CRUD — cadastrar e recuperar dados reais

Na versão 0.5.2, os componentes de entrada são mapeados para colunas sucessivas. No exemplo testado: txtNome → A, txtCidade → B, CheckBox → C e ComboBox → D.

ABCD
MariaNova FriburgoTRUEOpção A
JoãoRio de JaneiroFALSEOpção B

Adicionar linha acrescenta um registro na faixa lida; Localizar busca valores; Selecionar carrega TextBox, ComboBox e estado marcado/desmarcado; Salvar edição atualiza a linha; Remover linha compacta os registros nas colunas utilizadas. O limite demonstrativo é de 40 linhas, e essas operações não são transações atômicas.

6. JavaScript e Monaco — como a integração funciona

// Exemplo funcional observado na versão Code Studio:
const celula = await wmk.sheet.getCell('A1');
const resultado = Number(celula.value) * 2;
await wmk.sheet.setCell('B1', resultado);
console.log('B1 atualizado:', resultado);

Esse código usa as funções disponibilizadas pelo ambiente web e a API local. Em teste real, quando A1 era 222, a célula B1 recebeu 444. O SDK ainda não fornece todos os recursos avançados de uma API de planilhas, como formatação, tabelas dinâmicas, eventos automáticos e transações.

Para editar comportamento visual, o próximo passo técnico é um registro formal de eventos de componentes (por exemplo, OnClick e OnChange) que execute scripts autorizados. O botão de CRUD atual não deve ser confundido com um sistema universal de eventos pronto.

7. Como criar controles derivados e plugins

Estado atual: o Designer possui um conjunto de controles implementado no código. Ainda não existe um carregador genérico de plugins externos. O exemplo abaixo é um manifesto proposto para a evolução do Component SDK.

{
  "id": "wmk.currency",
  "name": "WMKCurrency",
  "version": "1.0.0",
  "extends": "TextBox",
  "properties": {"currency": "BRL", "decimals": 2},
  "events": ["change", "validate"]
}

O futuro SDK deverá definir: (1) contrato JSON; (2) renderizador e editor de propriedades; (3) serialização do valor; (4) eventos; (5) versionamento; (6) testes; (7) permissões para integrações. O novo componente poderá se basear em TextBox, mas deverá receber um identificador próprio para evitar conflitos.

Exemplos de controles úteis: CPF/CNPJ, CEP, moeda, DatePicker, RadioGroup, TreeView, máscaras, editor rico, gráfico, leitor de código de barras e DataGrid com filtros. A implementação deve ocorrer por interfaces documentadas, não por acesso irrestrito ao servidor.

8. IA, Skills, MCP e integrações — roteiro futuro

O objetivo é permitir provedores como Ollama, Groq, OpenAI e Gemini por meio de adaptadores, com autenticação no backend, controle de custos e permissões para ferramentas.

PeçaPapel futuro
AI ProvidersModelos, endpoints, chaves e política de custos
Chat IAGerar fórmulas, formulários, JavaScript e relatórios
SkillsManuais operacionais que ensinam o agente a utilizar recursos WMK
MCP ServerExpor ferramentas como ler intervalo, escrever célula e listar planilhas
APIs externasConectar bancos, serviços, relatórios e sistemas autorizados

Essas integrações não estão disponíveis como módulos finalizados na v0.5.2. A prioridade é criar contrato de API estável, autenticação e confirmações para ações destrutivas.

9. Logo e paleta WMK Formula

Utilize a logo oficial fornecida pelo mantenedor. Cores principais (referências da arte): verde WMK #00C853, verde escuro #0B3D2E, laranja #FF8A00 e prata #E0E0E0. Interface escura: fundo #0A0F14 e painéis #111A24. Prefira Segoe UI, com alternativas Inter/Roboto/Noto Sans. Verifique contraste em componentes de texto e estados de erro.
